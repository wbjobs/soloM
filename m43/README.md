# WebRTC P2P 文件传输与剪贴板同步工具

基于 WebRTC 技术的局域网 P2P 文件传输与剪贴板同步 Web 应用。无需上传服务器即可在两台电脑间直接传输文件和同步剪贴板内容。

## 功能特性

- **P2P 文件传输**: 通过 WebRTC DataChannel 直接在设备间传输文件
- **断点续传**: 支持大文件断点续传逻辑
- **拖拽上传**: 支持拖拽文件进行传输
- **剪贴板同步**: 实时同步两台设备的系统剪贴板内容
- **房间机制**: 通过房间号进行设备配对
- **实时日志**: 详细的连接和传输日志

## 技术架构

### 后端 (FastAPI)
- 仅作为 WebSocket 信令服务器
- 负责交换 SDP Offer/Answer 和 ICE Candidates
- 不存储或转发任何文件数据

### 前端
- **signaling.js**: WebRTC 信令交换逻辑
- **fileTransfer.js**: DataChannel 文件分片传输模块
- **clipboardSync.js**: 剪贴板同步模块
- **app.js**: 主应用程序和 UI 交互

## 安装与运行

### 1. 安装 Python 依赖

```bash
cd backend
pip install -r requirements.txt
```

### 2. 启动服务器

```bash
python main.py
```

服务器将在 `http://localhost:8000` 启动。

### 3. 使用方法

1. 在两台电脑上分别打开浏览器访问 `http://<服务器IP>:8000`
2. 两台设备输入相同的房间号（或点击"随机生成"）
3. 输入各自的设备名称
4. 点击"连接"按钮
5. 等待 P2P 连接建立成功

### 文件传输

1. 连接成功后，拖拽文件到拖拽区域，或点击选择文件
2. 文件将自动通过 P2P 传输到对方设备
3. 可以暂停/继续/取消传输
4. 接收方会自动下载文件

### 剪贴板同步

1. 连接成功后，启用"剪贴板同步"开关
2. 任何一方复制的文本内容会自动同步到另一方
3. 也可以手动点击"发送本地剪贴板"主动同步

## 功能更新 (v1.2)

### 新增：房间密码与 SDP 加密

为确保信令交换阶段的隐私安全，新增房间密码功能，对 SDP 信息和 ICE 候选进行 AES 加密。

#### 功能说明

**加密机制**:
- **算法**: AES-GCM 256位
- **密钥派生**: PBKDF2 with SHA-256 (100,000 次迭代)
- **随机数**: 每个加密消息使用独立的 16 字节 salt 和 12 字节 IV
- **完整性**: GCM 模式提供消息完整性验证，防止篡改

**加密内容**:
- SDP Offer/Answer (包含媒体能力、网络地址等敏感信息)
- ICE Candidates (包含 IP 地址、端口等网络信息)

**信令服务器**:
- 仅转发加密后的密文，无法解密任何内容
- 无法获取 SDP 或 ICE 候选中的任何敏感信息
- 真正实现端到端的信令隐私保护

#### 使用方法

1. 两台设备输入相同的房间号和房间密码
2. 系统自动使用密码对信令消息进行加密
3. 接收方使用相同密码解密消息
4. 如果密码不匹配，解密失败并在日志中提示

#### 安全特性

- ✅ 密码仅保存在浏览器内存中，永不发送到服务器
- ✅ 断开连接时自动清除密码
- ✅ 每个消息使用独立的随机 salt 和 IV，避免重放攻击
- ✅ GCM 模式提供消息完整性验证
- ✅ 100,000 次 PBKDF2 迭代，抵抗暴力破解
- ✅ 信令服务器只转发密文，无法获取明文内容

## 修复更新 (v1.1)

### 问题修复

#### 1. DataChannel 缓冲区溢出问题修复
**问题**: 传输超过 100MB 大文件时，DataChannel 缓冲区溢出导致传输中断且无报错。

**解决方案**:
- **滑动窗口流控**: 实现基于窗口的流量控制，每次最多发送 50 个未确认分片
- **ACK 确认机制**: 接收方收到每个分片后发送确认包，发送方根据 ACK 滑动窗口
- **超时重试机制**: 每个分片发送后启动 5 秒超时定时器，最多重试 5 次
- **缓冲区监控**: 使用 `bufferedamountlow` 事件，缓冲区低于 256KB 时自动继续发送
- **错误捕获**: 所有 `send()` 操作包裹 try-catch，异常时记录日志并自动重试
- **状态显示**: 添加 "错误" 状态和重试按钮，传输失败时用户可手动重试

#### 2. NAT 穿透失败问题修复
**问题**: 复杂 NAT 网络环境下（如对称型 NAT），P2P 连接建立失败，且无回退机制。

**解决方案**:
- **多 ICE 服务器**: 配置 5 个 Google STUN 服务器 + 4 个公共 TURN 服务器（Cloudflare、OpenRelay）
- **ICE 收集超时**: 设置 10 秒 ICE 收集超时，超时后强制使用已收集的候选
- **连接超时检测**: 设置 30 秒 ICE 连接超时，超时后自动尝试 ICE 重启
- **ICE 自动重启**: 检测到 ICE 失败或断开时，自动触发 ICE 重启流程
- **完整状态监听**: 监听 `icegatheringstatechange`、`iceconnectionstatechange`、`connectionstatechange` 全部事件
- **详细日志**: 所有 ICE 状态变化和候选信息都记录到日志，便于排查问题

## 注意事项

1. **浏览器权限**: 首次使用时需要授予剪贴板访问权限
2. **网络环境**: 已内置 TURN 服务器支持，公网环境也可正常使用
3. **文件大小**: 理论上支持任意大小文件，使用 16KB 分片，滑动窗口确保稳定传输
4. **浏览器兼容性**: 建议使用 Chrome/Edge/Firefox 最新版本
5. **大文件传输**: 传输超过 1GB 文件建议保持页面在前台，避免浏览器后台节流

## 安全说明

- 所有数据通过 P2P 直接传输，不经过服务器
- 信令服务器仅用于建立连接，不存储任何用户数据
- 建议在可信网络环境下使用
