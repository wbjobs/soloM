## 1. 产品概述

DICOM 医学影像解析与渲染系统是一个面向医学影像工作者和开发者的全栈 Web 应用，提供 DICOM 格式影像文件的上传、存储、元数据解析和可视化渲染功能。系统采用 WebAssembly 技术实现浏览器端高性能元数据解析，结合 cornerstone.js 实现专业级医学影像渲染与窗宽窗位调节。

- **目标用户**：放射科医生、医学影像研究人员、PACS 系统开发者
- **核心价值**：零安装、浏览器端即可完成 DICOM 影像的查看与基础调节，WASM 加速的元数据解析提供近原生性能

## 2. 核心功能

### 2.1 用户角色

| 角色 | 使用方式 | 核心权限 |
|------|----------|----------|
| 影像浏览者 | 直接访问 | 浏览文件列表、查看影像、调节窗宽窗位 |
| 影像上传者 | 直接访问 | 上传 DICOM 文件、浏览、查看、调节 |

### 2.2 功能模块

1. **影像管理页**：文件上传、文件列表展示、元数据摘要显示
2. **影像查看页**：Canvas 渲染黑白影像、窗宽窗位实时调节、DICOM 元数据详情面板

### 2.3 页面详情

| 页面名称 | 模块名称 | 功能描述 |
|----------|----------|----------|
| 影像管理页 | 文件上传区 | 拖拽或点击上传 .dcm 文件，支持多文件上传，显示上传进度 |
| 影像管理页 | 文件列表 | 以列表/卡片形式展示已上传的 DICOM 文件，显示文件名、患者姓名、检查日期、扫描层厚等摘要信息 |
| 影像查看页 | Canvas 渲染区 | 使用 cornerstone.js 在 Canvas 上渲染原始医学黑白影像 |
| 影像查看页 | 窗宽窗位控制 | 提供滑块和数值输入调节窗宽(Window Width)和窗位(Window Level)，支持预设值（如骨窗、肺窗、脑窗） |
| 影像查看页 | 元数据面板 | 展示 WASM 模块解析出的完整 DICOM 元数据（患者姓名、检查ID、扫描层厚、像素间距等） |

## 3. 核心流程

用户打开系统 → 上传 DICOM 文件 → 服务端存储并返回文件信息 → 前端文件列表刷新 → 点击文件 → 前端通过 WASM 解析元数据 → 使用 cornerstone.js 渲染影像 → 用户调节窗宽窗位实时更新显示

## 4. 用户界面设计

### 4.1 设计风格

- **主色调**：深蓝黑 (#0a1628) 为底，冷蓝 (#3b82f6) 为强调色，呼应医学影像的专业冷色调
- **次色调**：浅灰 (#e2e8f0) 文字，青蓝 (#06b6d4) 辅助高亮
- **按钮风格**：圆角矩形、轻微 3D 凸起效果，hover 时发光
- **字体**：JetBrains Mono 用于数据展示，Noto Sans SC 用于中文界面文字
- **布局风格**：左侧文件列表面板 + 右侧影像渲染主区域，顶栏工具条
- **图标风格**：线性图标，stroke-width 1.5，与医学界面的精确感匹配

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 元素 |
|----------|----------|---------|
| 影像管理页 | 文件上传区 | 虚线边框拖拽区域、蓝色上传图标、进度条动画 |
| 影像管理页 | 文件列表 | 深色卡片列表、患者姓名高亮、层厚/日期标签 |
| 影像查看页 | Canvas 渲染区 | 黑色背景 Canvas、影像居中显示、角落信息标注（患者名/检查日期） |
| 影像查看页 | 窗宽窗位控制 | 双滑块组件、数值输入框、预设按钮组（骨窗/肺窗/脑窗/软组织窗） |
| 影像查看页 | 元数据面板 | 右侧可收起面板、键值对表格、滚动查看 |

### 4.3 响应式设计

- 桌面优先设计，最小宽度 1280px
- 文件列表在窄屏下可折叠为侧边抽屉
- Canvas 渲染区自适应容器尺寸
- 窗宽窗位控制在移动端简化为手势操作

### 4.4 动效设计

- 文件上传时：拖拽区域呼吸动画、上传进度流光效果
- 影像加载时：Canvas 区域淡入效果
- 窗宽窗位调节时：实时响应无延迟
- 列表项 hover：轻微浮起 + 边框发光
